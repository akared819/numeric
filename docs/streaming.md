# Running mean core operation

`running_mean` consumes exactly one finite Float64 scalar sample per `execute` and returns two Float64 scalar outputs: the running mean and accepted sample count. Each successful call counts one sample; invalid inputs are rejected without changing state. A caller must not interpret repeated execution as a new sample unless its own triggering protocol guarantees that. This initial core API does not expose streaming to EPICS records and does not infer sample events from input links.

The first accepted sample produces that value and count 1. There is no zero-sample output: `reset()` clears the workspace and the next successful execution again returns count 1. Counts are exact up to 2^53, or the platform's smaller `size_t` limit; updates beyond that limit are rejected. Input/output descriptors require a scalar, count and capacity at least one, unit input stride, distinct output buffers and Float64 types. On failure both output counts are cleared and output values remain unchanged. Non-finite inputs are invalid. GSL update errors or non-finite means invalidate the accumulator until reset, since the update may already have changed its internal state. Reset failures leave the instance invalid. No variance convention is defined by this operation.

Call `initializeGsl()` during single-threaded process startup before creating a running operation: its factory allocates the GSL workspace and returns null if GSL is not initialized or allocation fails. Each instance owns its `gsl_rstat_workspace` and frees it on destruction; no allocations are made per update. Do not use a single instance concurrently without synchronization. Independent instances have independent sample counts and resets. These guarantees depend on all process participants honoring the global GSL error-handler policy in [architecture](architecture.md). See [GSL running statistics](https://www.gnu.org/software/gsl/doc/html/rstat.html).

This is a small core increment: an EPICS streaming interface, event identity, duplicate handling, reset PV and IOC integration tests remain to be designed before streaming data is accepted through a PV.
