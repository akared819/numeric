# Uniform histograms

`histogram_uniform` bins one nonempty contiguous DOUBLE sample array using GSL's [`gsl_histogram`](https://www.gnu.org/software/gsl/doc/html/histogram.html) API. It takes three additional DOUBLE scalar inputs, in order: lower bound, upper bound and number of bins. Bounds must be finite and strictly ordered, their difference must be finite, and the bin count must be an integer from 1 through 65,536. The output is a DOUBLE array of that many bin counts. Output capacity must cover every bin.

The uniform range is **lower-inclusive and upper-exclusive**. Every sample must be finite and within `[lower, upper)`; the whole calculation is rejected if any sample is outside that range, rather than silently omitting it. For example, samples `[0,0.25,0.5,0.75,0.999]` with range `[0,1)` and four bins produce `[1,1,1,2]`. Bin edges follow GSL's floating-point uniform-range calculation. If the requested range and count produce indistinguishable adjacent edges, the operation returns `NumericalError`. Sample counts are limited to 2^53 so integer bin counts are exactly representable as DOUBLE.

The input stride is one and its capacity must cover the valid samples. Input and output may overlap: the histogram is fully accumulated before output is written. Input/parameter validation failures return `InvalidArgument`; allocation, unrepresentable edges or GSL errors return `NumericalError`. Failure clears the output count and preserves the existing output buffer. The operation owns one reusable GSL histogram per instance; it allocates on first use or when the bin count changes, clears and reconfigures bins for each calculation, and frees the workspace on reset or destruction. It does not retain a running history. Do not execute the same instance concurrently. Initialize the process-wide non-terminating GSL policy as described in [architecture](architecture.md#gsl-setup-for-an-ioc).

The [numericArray record](numeric-array.md) exposes OP `histogram_uniform`: INP is the DOUBLE sample waveform, HMIN and HMAX are bounds, NBIN is the integer bin count, and OMAX must be at least NBIN. VAL contains counts, NORD equals NBIN on success and NIN is the input sample count. Failed processing preserves VAL and NORD, sets NIN to zero and raises CALC/INVALID. Parameter and source updates do not automatically process the record and must be coordinated by the producer. [array.db](../examples/array.db) supplies `demo:arrayHistogram`; write `demo:arrayInput`, explicitly process the record and inspect VAL and SEVR. The histogram fields extend the record DBD; rebuild IOC applications using the updated record definition and support library together.
