# Acknowledged streaming protocol

`numericAcknowledgedStats` is a single-producer, one-event-at-a-time aSub interface. It uses one DOUBLE waveform for the entire event so sample and identity are fetched together. It is not a general-purpose queue: reliable delivery within a running session requires the producer to follow the acknowledgment protocol below. Independently writing or overwriting the event waveform without waiting for acknowledgment can lose events.

Call `numericInitialize` after registering the IOC support and before `iocInit`. Use [acknowledged-stats.db](../examples/acknowledged-stats.db): the passive, synchronous soft waveform must have a **local database forward link** to the passive aSub record, and the aSub must read that waveform through a **local database input link**. Do not force either link through Channel Access. Do not disable, periodically scan, or separately process either record. The waveform VAL field processes the waveform on a CA put; its forward link then processes the aSub under the same database lock set. The sender requires this configuration and cannot verify it remotely. Configure the waveform with `NELM` at least 5 and input A as DOUBLE with `NOA` at least 5; each valid input must contain exactly four DOUBLE values `[session, sequence, kind, value]`. A fifth element is rejected, including when the input is truncated at capacity. Use a scalar-output DOUBLE `aSub` record with `SNAM=numericAcknowledgedStats`. Its first seven outputs, VALA–VALG, are mean, sample variance, sample standard deviation, RMS, minimum, maximum and count. VALH is the acknowledged session, VALI the sequence, VALJ the event kind and VALK the event value. Outputs VALA–VALK must be scalar DOUBLE fields. For the sender, configure VALL as DOUBLE with NOVL at least 11; it contains one coherent snapshot `[mean, sample variance, sample standard deviation, RMS, minimum, maximum, count, session, sequence, kind, value]`. NEVL is 11 on success and zero on rejection. The example forwards session and sequence to separate PVs for display; those PVs are not an atomic acknowledgment. Variance and standard deviation are NaN after the first sample. Reset yields NaN for statistics and zero count.

The session is an integer in `[1, 2^53]`, chosen uniquely by the producer for each new stream lifetime. The first sequence is zero; subsequent sequences increase by exactly one up to `2^53`. Kind 0 is a sample, and `value` must be finite. Kind 1 is a reset, and `value` must be zero. A reset is an ordered event and consumes a sequence number. When the IOC, record, or subroutine is restarted or replaced, its state is lost: the producer must choose a new session identifier and begin at sequence zero. Session reuse across restarts cannot provide exactly-once behavior. In particular, after a restart an old sequence-zero event can be accepted as the first event of a new stream; its acknowledgment cannot establish whether that event was also processed before the restart. Detecting restarts and reconciling lost state are the integrator's responsibility.

For each event, a single coordinated producer must:

1. Write the complete waveform. The local forward link processes the aSub under the same database lock set; do not issue a separate `.PROC` write. A plain CA put can be dropped, so it is never itself evidence of delivery.
2. Poll all 11 elements of VALL in a single Channel Access array get and check the returned count is exactly 11. Accept the snapshot only when session, sequence, kind and value match the submitted event. The seven statistics in that same snapshot accompany the acknowledgment. Channel Access put completion alone is not the numerical acknowledgment.
3. Do not submit the next event until acknowledgment. On a lost or ambiguous response, retry the identical event. The consumer replays the retained acknowledgment without updating state twice. A late old waveform write is processed together with that write while the lock set is held: it is rejected if a later event has already been accepted, and cannot overwrite an unprocessed newer event. A repeated sequence with a different kind or value, a sequence gap, a lower sequence, a different session, an invalid sample or malformed packet is rejected with CALC/INVALID.

An old delayed request can still change the record's status after a newer event is processed. Therefore an empty or mismatched snapshot is **uncertain**, not proof that the current event was rejected. Retain the current event and investigate or retry it; never advance solely on completion of a CA write. The snapshot is the coherent response; individual output fields and output links do not form an atomic read. Independent processing or writers are prohibited.

This is cooperative backpressure: the IOC does not reserve the waveform slot or enforce exclusivity against another client. It does not persist samples or acknowledgments over an IOC crash, detect overwritten events before its first processing, or guarantee delivery if a producer violates the protocol. Multiple independent writers require an external arbiter. Session and sequence output links are separate EPICS operations, not an atomic pair; read them only after the matching process completion while holding the single-producer discipline. If a numerical failure poisons the workspace, an ordered reset can be sent using the still-expected sequence; the failed sample is not acknowledged. A reset allocates a new workspace before replacing the old one, and a failed allocation leaves the prior acknowledgment intact. GSL's documented upstream allocation-failure caveat still applies.

## Native Channel Access sender

The build provides `numericAckSend`, a native command-line producer for a single event. With the example database loaded using prefix `demo:`, run these commands in order:

```sh
numericAckSend demo:event demo:acknowledgedStats 57 0 sample 1.5
numericAckSend demo:event demo:acknowledgedStats 57 1 sample 2.5
numericAckSend demo:event demo:acknowledgedStats 57 2 reset
```

Both the waveform forward link and the aSub input must be local database links as in the example; the passive waveform and aSub must process synchronously. Configure Channel Access addressing for the IOC as usual. The sender issues a plain CA waveform put and polls the complete VALL snapshot, verifying all four acknowledged event fields before printing the seven statistics. A put can be dropped or its processing delayed; the matching snapshot is the only success signal. It attempts the identical event up to three times, with a five-second connection timeout and a five-second snapshot polling deadline per attempt. Exit status 0 confirms acknowledgment; 1 reports invalid input; 2 means the outcome is uncertain, including an empty or mismatched snapshot. After an uncertain outcome, retain and retry the **identical** event before sending a later sequence. An empty snapshot can indicate a sequence or input error or interference from a delayed request; inspect the IOC state when retries cannot resolve it.

The executable does not choose or persist session numbers, queue events, arbitrate multiple producers, or recover IOC state after restart. The caller must ensure only one event is in flight and maintain its event and sequence across process invocations. Retrying does not make an uncoordinated producer lossless.

The native `numeric::AcknowledgedStream` API in `numericAck.h` implements the same sequencing and caches the last response. `create()` requires GSL initialization and can return null; allocation exceptions can propagate. `submit()` reports errors without replacing the caller's acknowledgment, and sets `replayed` on identical retries. Callers must serialize access to each instance. Each instance owns its GSL workspace and releases it on destruction. The IOC adapter stores one instance per record, releases it when the aSub routine changes or at process exit, and does not support dynamic database deletion/recreation within a process.

The native and IOC suites test sequencing, duplicate identity, invalid inputs, reset, independent instances, and oversized packets. `tests/network-ack.sh` starts a separate test IOC and runs CA clients over loopback, matching the sender's standalone deployment. A test-only synchronous delay causes the sender to time out and destroy its CA context while the IOC is still processing; a separate read verifies that the IOC subsequently accepted the event, then a retry verifies the count remains one and the next sample advances it. The test also terminates and starts the IOC process, verifies that an old nonzero sequence is not acknowledged and a new session starts empty, and demonstrates the ambiguity of reusing a first event. These tests do not simulate a general network partition, a crash during processing, arbitrary concurrent writers, or durable recovery. The sender uses plain puts rather than put-notify callbacks; Linux CI also repeats the original same-process regression because earlier same-process put-notify tests intermittently crashed in EPICS Base 7.0.10 notification handling. See [EPICS process notification](https://docs.epics-controls.org/en/latest/appdevguide/lockScanProcess.html) and [CA put callback semantics](https://docs.epics-controls.org/projects/base/en/7.0.10/cadef_h.html).
