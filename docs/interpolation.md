# Linear interpolation

`interp_linear` evaluates a piecewise linear interpolant using the [GSL interpolation API](https://www.gnu.org/software/gsl/doc/html/interp.html). Its native inputs are contiguous DOUBLE arrays `x` and `y` followed by a scalar DOUBLE query. Arrays must have the same length (at least two), finite values, and strictly increasing `x` with representable finite interval widths. The query must be finite and inside the closed interval from the first to the last `x`. The output is one DOUBLE. Invalid inputs, allocation failures, GSL errors and non-finite results are rejected; the previous output is not overwritten on failure.

An operation instance owns its interpolation object and lookup accelerator. It reuses them for the same number of points, reallocates the interpolation object if that number changes, and releases both on reset or destruction. GSL does not retain the caller's arrays. A single instance must not be executed concurrently; use separate instances for concurrent calculations. Allocations can occur when the size changes, so this is not a hard-real-time interface.

`numericInterpLinear` is the aSub interface. A and B are DOUBLE waveforms for x and y, C is a scalar DOUBLE query and VALA is the scalar result. For waveform links, reserve one extra input element in NOA and NOB to detect potential truncation; the links must expose DOUBLE data. The query and output links must have scalar capacity and use DOUBLE. The example in `examples/interpolation.db` supports four source points and reserves five elements in each aSub input. The record must be explicitly processed. Inputs are fetched separately; producers must coordinate updates to avoid mixing datasets. Failure raises CALC/INVALID and leaves the previous output unchanged. See [architecture](architecture.md) for initialization and the process-wide GSL handler policy.

Only one-dimensional linear interpolation is implemented; other interpolants, extrapolation, derivatives and integration are outside this increment.
