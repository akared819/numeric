# Phase 5: representative GSL coverage

The agreed completion target is at least one documented, tested representative capability in every category listed in [GSL coverage](gsl-coverage.md). This is a minimum coverage milestone, not complete coverage of each category or of GSL. Categories already covered by Phases 2–4 retain their existing evidence. Each new increment must document its exact algorithm, native input/output and EPICS access, validation, errors, ownership and limits; include meaningful numerical and invalid-input tests plus IOC tests where applicable; update coverage; and pass required Linux CI before review and merge.

At the start of Phase 5 the unevaluated categories included histograms; interpolation; numerical differentiation and integration; linear algebra; special functions; polynomials; random numbers and probability distributions; least squares and fitting; roots, optimization and ODE solvers; and other GSL modules. Consult the coverage table for current status. A capability in each *listed category* is the acceptance minimum; grouped categories do not imply complete support for all their subfields. Stateful, callback, workspace and asynchronous execution contracts must be designed per capability rather than assumed to share a signature. Any impractical or unsafe category must remain open or be explicitly documented and approved as an exception.

Phase 5 continues the process-wide GSL non-terminating error-handler policy and the existing documented EPICS Base notification-crash limitation. It does not introduce Python or another mandatory numerical dependency. After the representative milestone, systematic expansion and performance work remain ongoing.
