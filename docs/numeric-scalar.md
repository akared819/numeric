# numericScalar record

`numericScalar` is a synchronous EPICS record that reads one DOUBLE scalar or waveform through INP and returns a scalar VAL using a compatible stateless array-to-scalar numeric registry operation. Configure OP at database load time (default `mean`); supported current names include `mean`, `variance`, `stddev`, `population_variance` and `population_stddev`. OP must resolve to exactly one DOUBLE array input and one DOUBLE scalar output and must not be stateful. Record fields OP and NMAX are not modifiable at runtime. The record does not support multi-input or multi-output operations.

Set NMAX to the largest input count (1 through 1,048,576). The record allocates NMAX+1 doubles during initialization, reads at most that many, and rejects an input longer than NMAX rather than silently truncating it. The input link must be nonconstant and report DOUBLE type; other numeric types are not converted by this interface. NORD reports the number of input elements used in the last successful calculation and becomes zero on failure. VAL and NORD are read-only to clients; PREC controls display precision.

Call `numericInitialize` after registering support and before `iocInit`. On each process, the record fetches the input, validates and invokes the selected core operation. A successful calculation updates VAL and NORD, clears UDF and posts value/log events. The timestamp is refreshed on every processing attempt. A fetch, validation, numerical, setup or initialization failure preserves the last VAL, clears NORD and raises CALC/INVALID. Alarm changes are posted to monitors; a forward link is processed after each attempt, including failures, and must inspect alarm state. Input updates do not automatically schedule record processing. An invalid OP or NMAX causes record initialization to fail; processing that record subsequently raises an invalid alarm.

Each record owns a separate operation instance and input buffer, allocated during record initialization. State is registered for deterministic cleanup at process exit; no global computational workspace is shared. The implementation does not support deleting and recreating databases dynamically in a running process, and it does not free its per-record buffers at IOC shutdown prior to process exit. Numerical execution does not allocate for the currently compatible batch statistics. The GSL process-wide policy and exception handling follow [architecture](architecture.md#gsl-setup-for-an-ioc).

For an IOC application, include both `numericSupport.dbd` and `numericScalarRecord.dbd` in its application DBD and link `numericIoc` and `numeric`. See [scalar.db](../examples/scalar.db) for mean and sample variance records. Write a waveform, explicitly process the desired record, and read VAL and SEVR. EPICS links can acquire data asynchronously and can report changing values; the record does not guarantee that every update is processed or that external data is stable across multiple PVs.
